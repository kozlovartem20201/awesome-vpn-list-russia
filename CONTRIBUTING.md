# Как внести вклад

Спасибо, что помогаете держать список актуальным. Здесь собраны правила для всех, кто предлагает сервисы или правки, включая владельцев VPN.

## Способы помочь

| Что вы хотите сделать | Как |
| :--- | :--- |
| Добавить VPN-сервис | [Форма «Добавить VPN в список»](https://github.com/kozlovartem20201/awesome-vpn-list-russia/issues/new?template=add-vpn.yml) — бот проверит заявку и сам откроет pull request |
| Сообщить, что сервис перестал работать, изменил цены или сайт | [Форма «Сообщить об изменении»](https://github.com/kozlovartem20201/awesome-vpn-list-russia/issues/new?template=update-vpn.yml) |
| Исправить опечатку, текст или раздел | Pull request с правкой `README.md` |
| Сообщить о фишинге, поддельном сайте или угнанном домене | Приватно, по инструкции в [SECURITY.md](SECURITY.md) |

## Критерии добавления

Сервис добавляется, если:

- он **стабильно работает в России** на момент заявки, желательно с подтверждением от нескольких пользователей;
- поддерживает хотя бы один **протокол с обфускацией**: VLESS Reality, VLESS/VMess/Trojan, Shadowsocks, Hysteria2, AmneziaWG, OpenVPN с обфускацией или собственный протокол с маскировкой трафика. Сервисы только со стандартными WireGuard, OpenVPN и IPSec не принимаются — в России их блокирует DPI;
- у него есть **опубликованная политика конфиденциальности** (No-Logs);
- **цены опубликованы** на официальном сайте;
- **домену не меньше 90 дней** — так отсекаются однодневки;
- нет задокументированных инцидентов со сливом данных пользователей;
- сервис не сотрудничает с Роскомнадзором и не передаёт данные российским властям.

Включение в список — не аудит и не гарантия безопасности. Мейнтейнер вправе отказать сервису, который выглядит подозрительно, даже если формально все проверки пройдены.

## Как работает заявка

1. Вы заполняете форму. Заявке автоматически ставится метка `submission`.
2. Бот проверяет ваш аккаунт, ссылки, тексты и сайт сервиса (подробности — ниже).
3. Если есть ошибки, бот перечислит их в комментарии и поставит метку `needs-changes`. Отредактируйте заявку — проверка запустится заново.
4. Если всё в порядке, бот откроет pull request: строку в сравнительной таблице, обзор сервиса и пункт оглавления. В комментарии к заявке будет ссылка и превью.
5. Мейнтейнер проверяет pull request вручную и мержит его. **Автоматически ничего не мержится.** После мержа заявка закрывается.

Правки заявки после открытия pull request обновляют его.

## Кто может предлагать сервисы

Правила защищают список от спама и сервисов-однодневок. Пороги лежат в [`.github/submission-policy.toml`](.github/submission-policy.toml).

- Аккаунту GitHub должно быть **не меньше 30 дней** (для pull request'ов с правками — 7 дней). Если у вас уже есть принятый pull request в этом репозитории, возраст аккаунта не важен.
- Не больше **одной открытой заявки** и **трёх заявок за 30 дней** с одного аккаунта.
- Заявки принимаются только от личных аккаунтов, не от ботов и организаций.
- Если честная заявка не прошла проверку (например, аккаунт свежий), напишите об этом в заявке — мейнтейнер может одобрить её вручную меткой `maintainer-approved`.

## Владельцам сервисов

Владельцы и сотрудники VPN-сервисов могут предлагать свои продукты, но должны **честно указать связь с сервисом** в форме. Такие pull request'ы получают метку `vendor-submitted`, а в описании появляется раскрытие. Скрытая связь с сервисом — повод удалить его из списка.

Тексты пишутся фактами:

- без рекламных слов: «лучший», «самый быстрый», «уникальный», «№1», «100%»;
- без восклицательных знаков, ссылок, `@`-упоминаний и Markdown-разметки — ссылки берутся только из отдельных полей формы;
- описание для таблицы — до 200 символов, для обзора — один абзац до 700 символов.

## Правила для ссылок

- Только **официальные** сайты и только `https://`.
- Без реферальных и партнёрских кодов, UTM-меток и других параметров трекинга (`?ref=`, `?utm_source=`, `?start=` у Telegram-ботов и т. п.).
- Без сокращателей ссылок (`bit.ly`, `clck.ru`, `vk.cc` и др.), IP-адресов, нестандартных портов, punycode и невидимых Unicode-символов.
- Сайт не должен перенаправлять на другой домен — указывайте конечный адрес.

### Смена домена

Если сервис переехал на новый домен, это нужно подтвердить: старый сайт перенаправляет на новый или есть официальное объявление сервиса. Pull request'ы со сменой домена у существующего сервиса получают метку `domain-change` и проверяются вручную — так чаще всего пытаются подменить ссылку на фишинговую.

## Pull request'ы напрямую

Правки текстов, исправления цен и опечаток можно присылать обычным pull request'ом. Учтите:

- **новые сервисы** от авторов без принятых pull request'ов закрываются автоматически с просьбой воспользоваться формой: она проверяет то же самое и сама соберёт правильную разметку;
- не удаляйте служебные HTML-комментарии `<!-- services:… -->` и `<!-- reviews:end … -->` — по ним бот находит, куда вставлять новые сервисы;
- у каждого сервиса из сравнительной таблицы должен быть обзор с заголовком `### Название`, а ссылки оглавления должны вести на существующие заголовки — это проверяет CI;
- правки `.github/`, `scripts/`, `tests/` и этого файла получают метку `sensitive-change` и требуют ревью владельца.

## Что проверяет бот

| Проверка | Если не прошла |
| :--- | :--- |
| Возраст аккаунта, лимиты заявок, блок-лист | заявка закрывается с объяснением |
| Ссылки: https, без рефералок, UTM, сокращателей, IP и punycode | ошибка, нужно исправить |
| Тексты: длина, без ссылок, `@`, HTML и рекламных слов | ошибка, нужно исправить |
| Хотя бы один протокол с обфускацией | ошибка: сервис не подходит |
| Сервиса ещё нет в списке (по названию и домену) | ошибка: дубликат |
| Название или домен похожи на уже добавленный сервис | PR получает метку `needs-manual-review` |
| Сайт, страница с ценами и политика открываются, нет редиректа на другой домен | ошибка или ручная проверка, если сайт закрыт защитой от ботов |
| Домену не меньше 90 дней (RDAP) | ошибка; у .ru и .рф даты нет в RDAP — тогда ручная проверка |
| Репозиторий клиента существует и не в архиве | ошибка |

Как всё устроено и как это настраивать, мейнтейнеры читают в [docs/MAINTAINING.md](docs/MAINTAINING.md).
